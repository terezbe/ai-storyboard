## הבריף המקורי

> מעברים יפים ואיטיים שמדגישים את התמונות. יש קטע ירח שצריך להופיע.

## הפייפליין

```
תיקיית תמונות
   │
   ├─ prep.py ─────────────────────────────────────────────┐
   │    EXIF orient → RGB                                  │
   │    חיתוך מרכזי ל-9:16 → 1620x2880 (פי 1.5 מהיעד)      │
   │    dedupe (colour-aware perceptual hash, סף 30/768)   │
   │    סידור: שרשרת שכן-קרוב לפי hash גרייסקייל          │
   │    יצירת שקופית ירח → הזרקה ב-62% מהרצף              │
   │    → prep/NNN.jpg + manifest.tsv + feature.txt        │
   │                                                        │
   └─ build.py ────────────────────────────────────────────┘
        pass 1: קליפ לכל שקופית  (מקבילי, ליבות-1)
        pass 2: צ'אנקים של 14 עם xfade  (מקבילי, 3)
        pass 3: חיבור סופי + bloom + גרעין
        → slideshow_9x16.mp4
```

### למה 1620x2880 ולא ישר 1080x1920

הזום נע בין 1.04 ל-1.16. אם היינו מכינים את השקופית ברזולוציית היעד,
הזום היה מותח פיקסלים קיימים והתמונה הייתה מתרככת. הכנה בפי 1.5 נותנת
מרווח — ffmpeg תמיד **מקטין** ולכן נשאר חד.

### חישוב אורך השקופית

```
sum(D_i) - (N-1) * FADE == TOTAL
```

כל מעבר "אוכל" 2.6 שניות מהאורך הכולל כי הוא חופף בין שתי שקופיות.
המשוואה פותרת את אורך הבסיס `D` כך שהסכום יוצא בדיוק היעד. שקופיות
מודגשות (הירח) מקבלות משקל 2.4.

האורך מחושב ב**פריימים** ולא בשניות — כדי שההחזקה בפועל תתאים בדיוק
למה שהמקודד מוציא, אחרת המעברים נסחפים והווידאו הסופי חורג מהיעד.

## תובנות טכניות מהבנייה

### 1. `zoompan` לא מתאים לפאן על תמונה סטטית

הניסיון הראשון לפאן העולה של הירח השתמש ב-`zoompan` עם `y` שמשתנה לאורך
הזמן. `zoompan` מצפה שהזום ישתנה, ופאן טהור בתוכו יצר עיוות. הפתרון:
`crop` שנע לאורך `t` על קנבס גבוה (4200px) ואז `scale` — פאן נקי לגמרי.

```
crop=1620:2880:0:'(ih-2880)*(1-ease)',scale=1080:1920
```

עם easing קוסינוסי `(1-cos(PI*t/dur))/2` — התחלה וסיום רכים.

### 2. שקופית מודגשת צריכה קלט לולאה

`zoompan` משכפל את הפריים הבודד בעצמו, אבל `crop` שמשתנה לאורך `t`
צריך זרם וידאו אמיתי. לכן שקופיות מודגשות מקבלות `-loop 1 -framerate 30 -t <dur>`.

### 3. hash גרייסקייל זורק וריאציות צבע

הגרסה הראשונה זרקה 9 "כפילויות" — בבדיקה ויזואלית התברר שרובן היו אותה
יצירה בגריידים שונים (ירוק/כחול, ורוד/צהוב). זה בדיוק מה שרוצים לשמור:
הן נראות מדהים כשהן נמסות זו לזו. המעבר ל-hash לפי ערוץ (768 ביט) השאיר
אותן ונשארו רק **2 כפילויות אמיתיות**.

### 4. מקביליות: threads ולא processes

הגרסה הראשונה השתמשה ב-`multiprocessing.Pool`. זה עובד על לינוקס (fork)
אבל **נשבר על Windows** — עם spawn הילד מייבא מחדש את המודול ו-`sys.argv`
שלו אינו הארגומנטים המקוריים, כך שנתיב ה-workspace אובד. בנוסף פונקציה
מקוננת (`render_chunk`) אינה ניתנת ל-pickle. מכיוון שכל worker רק ממתין
לתהליך ffmpeg, `ThreadPoolExecutor` נותן בדיוק אותה מקביליות והוא נייד.

### 5. `shell=True` עם מרכאות בודדות נשבר ב-Windows

`cmd.exe` לא מתייחס למרכאה בודדת כתו ציטוט, ולכן נתיב עם רווחים היה
נשבר. עברנו לפקודות כרשימה עם `shell=False` — הארגומנטים עוברים כמו
שהם, בלי תלות בשל.

## מתכוני התנועה

כל שקופית מקבלת בסיס Ken Burns ואז אחד משלושה טיפולים, לפי `i % 3`:

```python
# i % 3 == 0 — שובלי אור
split[a][b];[b]lagfun=decay=0.93[t];[a][t]blend=all_mode=lighten:all_opacity=0.55

# i % 3 == 1 — מריחת הד-תנועה
tmix=frames=9:weights='9 8 7 6 5 4 3 2 1'

# i % 3 == 2 — סטייה כרומטית + נשימת גוון
rgbashift=rh=3:bh=-3:edge=smear,hue=h='7*sin(2*PI*t/11)':s='1+0.06*sin(2*PI*t/7)'
```

הזום מתחלף פנימה/החוצה לפי זוגיות, והסחיפה הצידית מתהפכת כל שתי
שקופיות — כך שאין תחושה של דפוס חוזר.

**מעברים** (`TRANS`), במחזור של 12: `hblur`, `dissolve`, `distance`,
`smoothup`, `zoomin`, `dissolve`, `hblur`, `radial`, `distance`,
`circleopen`, `smoothdown`, `fadegrays`.
הכבדים באמורפיות הם `hblur` (בלור-מריחה), `distance` (מורפינג פיקסלים
לפי מרחק צבע) ו-`dissolve` (המסה רועשת).

## קטע הירח

נבנה ב-Pillow על קנבס 1620x4200 (גבוה, כדי שהפאן העולה יחשוף אותו):

1. גרדיאנט שמיים — אינדיגו עמוק → טורקיז לכיוון האופק (72% מהגובה)
2. גרדיאנט ים — טורקיז כהה → כמעט שחור
3. 420 כוכבים בגדלים ובהירויות אקראיים
4. הילה בארבע שכבות + גאוסיאן 140 → `screen`
5. דיסקת הירח עם 14 כתמי "ימים" עדינים, בלור 10 → `lighten`
6. עמוד השתקפות על הים — קווים בעובי 2 עם פיזור אקראי ופערי נצנוץ

`random.seed(7)` קבוע — התוצאה זהה בכל הרצה.

## איך זה נמסר בפעם הראשונה

הווידאו המלא (300MB) חורג ממגבלת 30MB להעברת קובץ, ולכן נחתך ל-15 קטעים
של ~40 שניות **בלי קידוד מחדש** (`-c copy`). לאיחוד חזרה לקובץ אחד:

```bat
(for %f in (phangan_9x16_part*.mp4) do @echo file '%f') > list.txt
ffmpeg -f concat -safe 0 -i list.txt -c copy phangan_full.mp4
```

בהרצה מקומית זה לא רלוונטי — מקבלים ישר קובץ אחד שלם.
